# Архітектура

Nuxt 4 із Vue 3, TypeScript strict, Composition API. SSR залишається увімкненим; `nuxt generate` пререндерить HTML у `.output/public`. Це артефакт майбутнього статичного хостингу; сервер застосунку для першої версії не потрібен.

```text
app/
  app.vue                 # NuxtPage
  pages/index.vue         # композиція SiteHeader, HeroSection, ServicesSection, AboutSection, BookingDialog
  components/             # лише компоненти під реальну потребу
  composables/            # useTextReveal: поява текстів у viewport
  data/                   # типізований локальний контент
  types/content.ts        # контентні моделі
  utils/formatPrice.ts    # окреме форматування числової ціни UAH
  assets/styles/          # global reset, provisional-токени, breakpoints
public/images/            # SVG-логотипи, три JPEG кабінету для hero
public/fonts/             # наразі порожньо
tests/smoke.spec.ts
docs/
assets-originals/         # незмінений AI-оригінал, не публікується
nuxt.config.ts
playwright.config.ts
```

## Дані

`Service`: id, slug, title, description, price, image, imageAlt, published. Ціна числова у гривнях; duration відсутнє. Неготові description/image/imageAlt — `null`, без фальшивих шляхів. Усі дев’ять послуг показуються на сайті як чернетка; прайс і описи потребують погодження Валентиною перед публічним запуском. Для фото перед публікацією додати фактичні розміри/джерела відповідно до отриманих активів.

`StudioImage`: src, alt, width, height, caption. `Review`: автор, текст, згода на публікацію. `Certificate`: фото, розміри, звірка оригіналу та згода. `Video`: джерело, постер, розміри, згода. `FaqItem`: запитання/відповідь. У всіх записів стабільний id. `ContactDetails`: телефон, email, адреса (поки null) та підтверджені канали. Всі інші колекції порожні. Не підставляти вигадані значення за відсутності даних.

## Компоненти

Реалізовані `SiteHeader`, `HeroSection`, `ServicesSection`, `ServiceCard`, `AboutSection`, `BookingDialog`. Блок знайомства використовує `AboutContent` із `app/data/about.ts`: тексти, підблок навчання та nullable-портрет. До отримання фото є лише типографічна монограма, а не фальшивий файл. Заголовки H2/H3 присутні в SSG HTML. Навігація «Про мене» веде на `#about`; на mobile закриває діалог меню, ціль доступна для фокуса. Дані й тексти винесені в `app/data/home.ts`. `index.vue` лише збирає компоненти й передає дію відкриття діалогу. Мобільне меню та діалог запису використовують HTML dialog: нативне модальне керування клавіатурою, Escape, початковий фокус і повернення фокуса; відкриваються лише після взаємодії на клієнті. `body:has(dialog[open])` обмежує прокрутку на час модального вікна, `scrollbar-gutter: stable` резервує місце скролбара.

Зображення hero — наданий користувачем файл кабінету. Picture використовує вертикальний JPEG 706×941 до 768px, від 768px повнокадрові JPEG 1280/1672w та sizes для cover (1672:941). Джерела мають відомі розміри, eager і high fetch priority; URL враховують Nuxt baseURL. Градієнт — окремий темний CSS-шар, alt описує кабінет. Hero резервує min-height 100svh, а прозорий header абсолютний поверх нього. Бежево-коричневі токени hero не змінюють світлі контентні секції. Див. [деталі](hero-studio.md). Попередні AI-фото більше не входять у public.

Решта — план, не реалізація:

- SiteFooter, MobileNavigation.
- StudioSection.
- VideoSection, ReviewsSection, CertificatesSection, FaqSection, ContactsSection.
- StudioGallery, VideoCard, ReviewCard, CertificateCard.
- BaseButton, SectionHeading, BaseDialog, AccordionItem — лише коли з’явиться реальна потреба.

Контент відокремлений від браузерних взаємодій. Local ref/computed для локального стану; Pinia без shared-state потреби не додається. Без CMS, Nuxt Content, UI-фреймворку, карусельної бібліотеки, GSAP, аналітики чи сторонніх API.

## Стилі та перевірки

Плавна поява текстів: спільний `_text-reveal.scss` для CSS-вступу hero й `useTextReveal` для текстів AboutSection через Intersection Observer + Web Animations API. Тривалість 1400ms та крива ease визначені спільними токенами. Базові стилі залишають контент видимим. За відсутності JS/Observer/animate або при помилці текст не залишається прихованим. Елементи About анімуються один раз, без приховування нижніх блоків наперед; невеликі затримки обмежені 300ms. Зміна reduced motion скасовує активні ефекти; observer, media-query listener та animations прибираються при знищенні компонента. При повторному створенні компонента після навігації механізм ініціалізується знову. Browser API викликаються лише в client lifecycle.

Навігація: `scroll-behavior: smooth` на html; за reduced motion — auto. Немає перехоплення природної прокрутки. Fullscreen mobile-menu зберігає нативний dialog/showModal, focus trap і фокус кнопки закриття. Панель займає 100dvh з safe-area відступами й власною прокруткою для низького екрана. Web Animations забезпечує вхід 420ms і вихід 315ms; без API або при reduced motion відкриття/закриття миттєві. Escape проходить через той самий анімований вихід. Перед переходом за якірним посиланням або відкриттям запису меню спочатку закривається; фокус і hash-навігація лишаються доступними. Listener налаштування руху та анімації прибираються при unmount. Для логотипа на поточну головну вимкнено зайвий prefetch, який залежав від Observer.

Час із CSS-токенів читається спільним `parseCssDuration`: підтримуються ms і s. Це суттєво для production, оскільки CSS-збірник може перетворити 420ms на .42s або 1400ms на 1.4s. Простий parseFloat без переведення одиниць використовувати не можна. Браузерний тест реєструє тривалості справжніх menu-анімацій і перевіряє, що вони не стали майже миттєвими; цей діагностичний атрибут додається тільки тестом, не кодом сайту.

SCSS scoped у компонентах, глобальні CSS custom properties в `_tokens.scss` (provisional). Mobile-first; єдині width-breakpoints у `_breakpoints.scss` (768/1200), `@use` з namespace і includes всередині селекторів. Hero: локальні шрифти з npm-пакетів @fontsource (Cormorant Garamond 500 + Manrope Variable), підключені в `nuxt.config.ts`; інші секції поки на системних шрифтах. Зовнішніх запитів до шрифтових CDN немає.

Prettier форматує, ESLint через офіційний Nuxt-модуль перевіряє код та порядок/lang SFC; eslint-config-prettier прибирає конфліктні стилістичні правила. TypeScript 5.9.3 — консервативна сумісна гілка, перевірка через vue-tsc. Lockfile генерує npm.

Smoke-тест і перевірки діалогу/меню повторюються у desktop/mobile Chromium на свіжому SSG-результаті: HTTP 200, lang, один очікуваний H1, noindex та відсутність помилок браузера/гідратації. Перевіряється перехід до «Про мене», фокус цілі та закриття mobile-меню. Mobile запускається з reduced motion. `serve` — лише dev-залежність для локального preview без SPA fallback. E2E не використовує чужий сервер. Browser-перевірки секцій, навігації, діалогів і анімацій додаються разом із відповідною реалізацією.

Не запускати dev/type-generation/build конкурентно з однією `.nuxt`. `build` перевіряє SSR, `generate` готує SSG; перевіряти саме артефакт, призначений для релізу, з тим самим оточенням. Публікація: GitHub Pages через `.github/workflows/deploy.yml` (пресет `github_pages`, base URL із `actions/configure-pages`). Локальні `preview` і E2E працюють зі збіркою для кореня `/`.

## Секція послуг — 17.11.2026

`ServicesSection` перед «Про Валентину» збирає дев’ять `ServiceCard` із наявного прайсу. На desktop фото чергуються, від 768px — дві колонки; mobile завжди фото над текстом. Контент читається у DOM послідовно. Заголовок, описи та ціни присутні в SSG HTML. `formatPrice` форматує числову ціну; тривалості немає. Поява текстів використовує наявний useTextReveal, без приховування SSR-контенту.

Поточна noindex-чернетка за запитом користувача показує весь чернетковий прайс, включно з published:false. Це явний попередній перегляд, не підтвердження цін для production. Перед відкриттям індексації перевірити ціни, описи, медіа та застосувати погоджений відбір published. Не переносити такий перегляд на production автоматично.

Фото ще не надані; image/imageAlt лишаються null, бежевий блок резервує aspect-ratio 4:3. Не підставляються випадкові або дубльовані кадри. Для фактичного фото потрібні imageWidth/imageHeight (optional у Service); img із lazy/async відображається лише з розмірами. Всі URL враховують baseURL. Користувач підтвердив, що голкотерапія — метод сухої голки з прогріванням: уточнено назву, додано опис Валентини, ціна 700 грн. Розслаблювальний масаж окремо не додано, бо ціна не надана.

Якір #services підключений у хедері, fullscreen-меню й hero; природний smooth scroll та reduced motion збережено.

Формат ціни: Intl.NumberFormat для числа та явний нерозривний пробіл + «грн». Валютний символ Intl не використовуємо: ICU у Node та Chromium може дати різні «₴»/«грн» й спричинити hydration mismatch.

## Картки послуг — 18.11.2026

За новим запитом замість рядків із чергуванням фото застосовано текстові картки в бежево-коричневій палітрі сайту. Сітка: одна колонка до 768px, дві від 768px, три від 1200px. Картка містить порядковий номер, H3, наданий опис, ціну й кнопку «Записатися». Кнопка відкриває наявний діалог із чесним поясненням статусу каналів запису, без імітації бронювання. Назви кнопок для assistive technology містять назву послуги.

Фото й порожні місця під них не відображаються. Наявна AI-ілюстрація масажу спини та її джерела в даних/файлах збережені, але компонент не завантажує їх. Нових зображень чи залежностей немає. Описи, ціни, noindex і статус чернетки залишаються. Текст карток видимий одразу в SSR; наявна поява заголовка секції з reduced motion збережена.

## Фонові AI-ілюстрації та компактні відступи — 18.11.2026

За прямим запитом користувача кожна з дев’яти карток отримує власну фотографічну AI-ілюстрацію в теплій бежево-коричневій палітрі. Це художні сцени, а не фото реальних клієнтів, Валентини чи її кабінету. Ілюстрація — декоративний абсолютний img на всю картку, під рівномірним CSS-шаром айворі (80%); текст і ціна залишаються HTML. Alt порожній: усю змістову інформацію передає текст картки. Є фактичні dimensions, srcset/sizes, lazy/async, baseURL. Фото не впливають на висоту картки; її визначає контент.

Сюжети відрізняються за послугами; дитячий масаж представлений рушниками й дерев’яною іграшкою, метод сухої голки — предметним процедурним натюрмортом. Оригінали зберігаються поза public. Походження та промпти — у docs/service-illustrations.md.

Секційні відступи зменшено з clamp(3rem,8vw,7rem) до clamp(2rem,4vw,3.5rem); від заголовка до карток — до clamp(1.5rem,3vw,2.25rem). Grid gap 24→16px, внутрішні відступи картки 28→18px, вертикальні проміжки теж зменшено. Сітка 1/2/3 колонки, діалог запису, контент і ціни збережені.

### Уточнення декору та оформлення карток — 18.11.2026

Орієнтир декору — надане фото справжнього кабінету: горизонтальна дерев’яна стіна, коричнева штора з теплою гірляндою, бежеві рушники та покриття кушетки. Не використовуємо вигадані вази, рослини, меблі чи інший spa-інтер’єр. Сцени масажу залишаються AI-ілюстраціями, а не документальними фото прийому.

Фон покриває всю картку включно з заголовком; висвітлення рівномірне, без градієнта. Радіус зменшено 20→8px; рамка 1px із приглушеною прозорістю 35%. Компактні відступи збережено.

## Повернення до рядків і перенесення фото — 18.11.2026

За запитом користувача послуги знову показані окремими рядками. Від 768px — фото та інформація у двох колонках, з чергуванням сторони фото. На mobile — фото над текстом. Фото повністю чіткі, без світлого шару та тексту поверх них; пропорція 4:3, заокруглення 3px. Збережено компактні секційні відступи, назви, описи, ціни й кнопки запису.

Ілюстрація з чоловіком із масажу спини перенесена до спортивного масажу (існуючі back-massage-720.jpg і back-massage-1448.webp). Для масажу спини тимчасово повторно використано сцену загального масажу з роботою по спині; це те саме зображення, не новий кадр. Фото передпліччя з попереднього спортивного масажу збережене у файлах, але не підключене. Остаточне окреме фото спини можна надати/погодити наступним.

ServiceCard збережено як компонент одного рядка; ServicesSection складає вертикальний список. Ілюстрації мають змістовні alt із позначенням AI-ілюстрації, фактичні розміри, srcset/sizes, lazy/async і baseURL. ResizeObserver прибрано: зображення тепер мають власну колонку 4:3 замість cover-фону на висоту тексту. Нових залежностей, зображень або бізнес-фактів не додано.

## Теплий фон контентних секцій — 18.11.2026

Користувач обрав тло на кшталт блоку кабінету з наданого зразка: тепла бежева основа й делікатна гра світла та тіні. Реалізовано спільними CSS-токенами color-content-background/background-content-image/background-content-size у _tokens.scss. Фон малюється на body, ServicesSection та AboutSection прозорі, тому між секціями немає розриву малюнка. Герой і світлі картки/діалоги зберігають власні фони. Це CSS-градієнти без додаткових зображень, фільтрів, fixed-ефектів або анімацій. Сам блок кабінету чи портрет із зразка не створювалися в цій задачі.

## Формати зображень — 18.11.2026

Растрові зображення сайту існують у трьох форматах з однаковими розмірами й кадром: AVIF і WebP генерує `npm run images` (`scripts/build-images.mjs`, sharp) з майстрів у `assets-originals`, JPEG — запасний варіант. Компоненти використовують `<picture>` із `source type="image/avif"`, `image/webp`, потім `img` з JPEG; шлях до інших форматів будується `withImageExtension`. Нове зображення: додати JPEG-похідні в public, запис у скрипт і запустити `npm run images`.

Контакти, карта та авторський підпис зберігаються в `app/data/contacts.ts`. `ContactsSection` і `BookingDialog` використовують спільні канали; `ContactIcon` містить SVG-іконки. `SiteFooter` використовує чинний рослинний знак. Старий експорт contacts із content.ts збережено для сумісності.

`SiteLogo.vue` перевикористовується хедером і футером: єдиний plant-mark.svg, однакова типографіка, currentColor. Контактний picture має джерела AVIF/WebP на всю площу секції та окрему вертикальну композицію до medium; підключення з app/data/contacts.ts.

AboutSection використовує реальне фото з responsive picture AVIF/WebP та типізованими sources в AboutContent. CertificatesSection збирає текст навчання й умовну галерею з app/data/content.ts; фільтр originalVerified && publicationApproved. Нативний dialog для документа, посилання на файл працює без JS. Непідтверджені документи не створюють карток у DOM.

ReviewsSection розташований перед FAQ. Дані й доступні цитати — app/data/reviews.ts; старий експорт reviews із content.ts збережено. Review описує скриншот із imageBase, розмірами, alt, nullable text та publicationApproved. Embla вже встановлена; використано спільні useReducedMotion/useCarouselImages. Діалог завантажує 1320px після взаємодії.
