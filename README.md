# Валентина Нечипоренко — сайт масажної практики

Односторінковий сайт: hero, послуги й ціни, «Про мене» із сертифікатами, переваги, відгуки, часті запитання, контакти та вікно запису. Тексти, ціни й частина медіа ще чекають погодження Валентиною (деталі в [прогресі](docs/progress.md)). Чернетка закрита від індексації через `noindex, nofollow`.

## Середовище та встановлення

Node.js **24.22.0** (`.nvmrc`), npm **11.19.1**. Підтримувана гілка проєкту: Node 24 від 24.22.0; `.npmrc` перевіряє engines. Початковий системний Node 20.20.2 не підходить обраному Nuxt. Якщо використовуєте nvm:

```bash
nvm use
npm ci
```

Якщо зазначеної версії Node немає, встановіть її командою `nvm install`. `npm ci` використовує наявний `package-lock.json`; не редагуйте його вручну. У чистому середовищі встановіть тестовий браузер:

```bash
npm exec playwright install chromium
```

## Робота локально

```bash
npm run dev
```

Dev-сервер зазвичай доступний на `http://localhost:3000`; точну адресу показує термінал.

```bash
npm run format
npm run lint
npm run typecheck
npm run generate
npm run test:e2e
```

`lint` також запускає `format:check`; доступний `lint:fix`. Перевірки Nuxt запускайте послідовно. Smoke-тест і перевірки діалогу/меню виконуються для desktop і mobile Chromium; тестовий запуск сам піднімає статичний сервер, але **не генерує** сайт. Перед тестом завжди запускайте `generate`. Порт 4173 має бути вільним; чужий сервер тест не використовує.

```bash
npm run generate
npm run preview
```

Статичний SSG-результат: `.output/public`, перегляд: `http://127.0.0.1:4173`. `preview` використовує локально встановлений `serve` без SPA fallback; невідомі URL повертають HTTP 404. Не запускайте preview паралельно з E2E на тому самому порту.

`npm run build` окремо перевіряє SSR-збірку; для її перегляду: `node .output/server/index.mjs`. Після `build` знову виконайте `generate`, якщо потрібен SSG-результат. Локально сайт збирається для кореня `/`; для підкаталогу див. розділ нижче.

## Публікація на GitHub Pages

Деплой виконує [workflow](.github/workflows/deploy.yml) після push у гілку `main` або вручну (Actions → Deploy to GitHub Pages → Run workflow). Він ставить залежності через `npm ci`, запускає `lint` і `typecheck`, збирає SSG із пресетом `github_pages` і публікує `.output/public`.

Перед першим запуском:

1. Створіть для проєкту окремий Git-репозиторій. Зараз папка лежить усередині батьківського репозиторію.
2. У Settings → Pages оберіть джерело **GitHub Actions**.
3. Base URL підставляється автоматично з налаштувань Pages: `/<назва-репозиторію>/` для project site або `/` для власного домену. Змінювати код не потрібно.

Перевірити збірку для підкаталогу локально (приклад для репозиторію `valentyna-massage`):

```bash
NUXT_APP_BASE_URL=/valentyna-massage/ NITRO_PRESET=github_pages npm run generate
```

Результат відкривається лише з підкаталогу `/valentyna-massage/`, тож для звичайного `preview` і E2E знову виконайте `npm run generate` без змінних.

Оригінали медіа з `assets-originals/` не потрапляють у Git (`.gitignore` лишає лише README). Зберігайте їх окремо. `npm run images` працює лише там, де є оригінали, а готові похідні для сайту лежать у `public/images`.
